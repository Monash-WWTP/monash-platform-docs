**Prerequisites:** verified citizen session with `report:own`, supported device permissions and a reachable API. A report requires a timezone-aware observation time, location and category-appropriate content.

<Steps><Step>
### Choose a category

| Category | Required value | Unit |
|---|---|---|
| Rainfall | Nonnegative numeric reading | mm |
| Water level | Nonnegative numeric reading | m |
| Temperature | Finite numeric reading | °C |
| Wastewater | Normal, warning or critical condition | No numeric reading/unit |

Do not swap a wastewater condition for a numerical measurement. Notes are optional and limited to 2,000 characters.
</Step><Step>
### Allow automatic location capture

Allow location access. The form captures location automatically and offers Retry if capture fails; it does not show editable coordinates, accuracy or observation time. It timestamps the report when you submit, so this form does not support entering a retrospective observation time. Resolve permission denial or unavailable GPS before submission. The API separately bounds coordinates, requires a timezone and rejects times more than five minutes into the future.
</Step><Step>
### Attach a photo if appropriate

Expand **Photo and note** to use Camera or Gallery and add an optional note. Closing this section retains entered details; its subtitle identifies a photo or note that has been added. Uploads are private and owned by the reporting account; the report references the resulting media ID. A missing or another user's media ID is rejected. Avoid including unnecessary identifying information in photos or notes.
</Step><Step>
### Submit and inspect history

The source client uses an idempotency key for retries. A lost response can be retried with the same key and identical payload; changing content while reusing the key returns 409. Confirm the report appears in your own history. It starts pending moderation, not public.
</Step></Steps>

## Recovery

For session expiry, sign in through the configured identity flow. For interrupted upload/submission, retry the same operation and confirm history before creating a new report. The server's idempotency contract does not establish unlimited offline queuing or automatic recovery after every app restart; real-device interruption acceptance remains open.

Read [report lifecycle](/docs/how-it-works/report-lifecycle) for privacy and ownership details.
