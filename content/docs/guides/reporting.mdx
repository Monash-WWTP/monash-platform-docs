<Callout type="warn" title="Source and release boundary">This describes the current shared-API client. The published legacy APK does not establish availability of these workflows. Use an accepted environment with verified identity and private storage.</Callout>

Start on **Map**, choose a point and report what you observed. A verified citizen account with `report:own` is required to submit. Review the location, observation time and content before sending.

## Choose an observation

| Type | Required context |
|---|---|
| Flooding | Whether water covers normally dry ground; affected surfaces when present |
| Rain occurrence | Present, not observed or unsure; this is not rainfall depth |
| Water appearance | Observed features, none observed or unsure; this is not a pollutant diagnosis |
| Rainfall accumulation | Gauge identity/type, timezone-aware start/end interval, mm value or explicit trace/missing |
| Water reading | Depth and surface reference, or instrument reading against an approved stage reference revision |
| Temperature | Air/water, instrument, sample context and known/unknown calibration provenance |

Do not turn trace/missing rainfall into numerical zero or an unsure observation into absence. The client negotiates supported revisions of `citizen-observation` through `/api/v2/observation-protocols`.

## Location, time and supporting details

Use current location or select a map point. GPS accuracy belongs to a current-location fix; a manually selected point must not imply measured accuracy. The observation form supports changing the observed time. The API requires a timezone and rejects times more than five minutes ahead; rainfall intervals cannot end after the observation.

An optional private photo can come from Camera or Gallery. Revision 2 records the picker source, which is not proof of the photo's capture time or authenticity. Notes are optional and limited to 2,000 characters. Photos remain private; public community output excludes photo paths and notes.

For an owned flooding observation, **Update here** can link a later observation at the same selected point. Optional context includes water movement and level change relative to the earlier observation. Moving the point clears the link. A follow-up is a new observation, not an edit to historical evidence.

## Review, submit and retry

Review the summary before sending. New submissions start pending moderation and appear in **My reports**. The client uses an idempotency key: identical content/key returns the existing submission; changed content with the same key returns 409. After a lost response, retry and check history before creating another report.

The server contract does not guarantee an unlimited durable offline queue or recovery across every app restart. Real-device interruption acceptance remains a release gate. V1 rainfall/water-level/temperature/wastewater records remain legacy compatibility records and must not be relabelled as protocol-qualified v2 observations.
