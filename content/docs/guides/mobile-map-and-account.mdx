The current source opens on **Map**, with **My reports** and **Account** as the other navigation destinations. The [interface gallery](/docs/guides/app-gallery) preserves older captures; it does not illustrate the latest map-first layout.

## Map and own history

The map combines approved v1 community records, supported v2 community observations and, when signed in, the owner's recent records. Records are merged by ID; the authorized own record replaces its public projection. Each initial request is bounded (normally 200 items), so the map is not a complete historical archive or live sensor feed.

Tap an observation for detail. Public positions are rounded; authorized own records may contain precise location, private notes and photos. **My reports** provides paginated owner history and review status. An owned flooding report can start a later **Update here** observation at the same point. A pending record visible to its owner is not public.

## Account settings

**Account** shows identity information and sign-in/out controls. Shared settings actions open the configured identity service for display name, email, password and session security. The API advertises only allowed flow URLs and only when `ACCOUNT_SETTINGS_ENABLED=true`; deployment must provision and test those flows first. The mobile client refreshes account proof when returning from settings and handles account changes without applying another user's stale response.

A citizen account does not confer operator capability. Email verification, password recovery and security-change revocation depend on the configured identity environment. A settings link or local test does not prove real mail delivery.

## Connectivity and privacy

Refresh or retry after transient failures. The source does not guarantee complete offline tile caching, a durable unlimited submission queue or background synchronization. Sign out clears local identity credentials and attempts provider end-session; broader revocation needs environment acceptance.

See [reporting](/docs/guides/reporting) for the observation protocol and [community observations](/docs/guides/community-observations) for public privacy boundaries.
