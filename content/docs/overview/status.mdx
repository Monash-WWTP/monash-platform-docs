## Latest local evidence

The preparation audit records 246 Python tests passed with one optional legacy-source-checkout skip, 50 dashboard tests, 59 Flutter tests and clean analyzer/lint/build checks where supported. Migration/OpenAPI and repository/inventory checks passed. The research notebook executed against 154 public final-effluent samples. None of these results establishes scientific validity.

Synthetic local staging on the new ARM64 server has working application/identity databases, private storage and API readiness. This is a new synthetic environment, not restoration of the former machine's private data. Public HTTPS health/placeholder routes are not a production API/account service, and further production rollout is paused. Real transactional email is not configured. The first release targets open public registration, so public abuse/capacity and identity enrollment protections remain launch requirements.

A local encrypted database restore reconciled 18 application and 230 identity tables. After an initial failure, investigation found and corrected a temporary-server readiness race in the restore helper; a regression and three real restores passed after the correction. The initial error did not expose enough diagnostics to prove its exact cause. A follow-up restored one synthetic PNG with matching SHA-256 and HTTP 403 for anonymous source/restored access; its post-fix local restore took 17.19 seconds. Off-server recovery, production-volume recovery, application ownership authorization and restored identity sign-in remain open.

The standard Android AAPT2 binary cannot run on this ARM64 host. Flutter source checks passed, but the supported-host GitHub workflow subsequently passed the debug APK build on `804e4f8`. Signed release and physical-device acceptance remain open. See [release gates](/docs/operations/release-gates).
