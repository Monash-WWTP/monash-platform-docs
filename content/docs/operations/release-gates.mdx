|---|---|---|

| 2 | Hosting and identity | Approved API/account origins, TLS/proxy/cookie/CSRF/callback checks; registration/email/recovery and invited operator MFA/revocation |
| 3 | Recovery | Named owner, acceptable loss/downtime and encrypted off-server app/identity/object restore rehearsal |
| 4 | Integration and migration | Real report/photo/retry/moderation/privacy, source export reconciliation and both clients against intended environment |
| 5 | Capacity and operations | Peak concurrency/photo volume, measured limits, redacted alerts, notification owner and incident exercise |
| 6 | Android | Original signing identity, increased code and physical install/upgrade/OIDC/offline/photo acceptance |
| 7 | Scientific scope | Research-only policy retained; separate calibration/validation/uncertainty and scientific authorization before decision use |
| 8 | Exact release | Immutable artifacts, migration/write procedure, rollback preserving new writes and observed acceptance window |

A separate Vercel `dashboard` project has a recorded root-directory build configuration failure. The successful `monash-water-platform` deployment does not establish backend cutover acceptance.

One minor code hardening item remains: malformed persisted simulation series containers fail closed with a server error rather than a structured incompatibility response. Map/chart bundle-size and dependency-deprecation warnings are also recorded.

## Evidence format

For each accepted gate, record owner, environment/date, exact revision/artifact, test steps/results, limitations and rollback point. Leave unperformed checks visibly pending. This manual supplies procedures and traceability, not approval to claim a complete production release.
