<Callout type="warn" title="Production acceptance is open">This is preparation guidance for implemented source, not a claim that the successor stack is publicly accepted. Confirm owners, domains, TLS, secrets, recovery and exact artifacts before cutover.</Callout>

<Tabs items={['Web platform','API and dependencies','Documentation']}><Tab value="Web platform">
Build with `npm --prefix apps/dashboard ci` and `npm --prefix apps/dashboard run build` from the platform repository. Configure the host's root as `apps/dashboard` and output as `dist`. The checked-in Vercel rewrite still targets the legacy Render API; changing that target requires approved API routing and integrated cookie/CSRF/callback acceptance.
</Tab><Tab value="API and dependencies">
Deploy the reviewed API with migrated application PostgreSQL, OIDC identity and private S3-compatible storage. Restrict database networking, inject secrets and qualify readiness, registration/recovery, operator MFA, report/photo/moderation and privacy. Pin images/artifacts and record migrations and rollback checkpoints.
</Tab><Tab value="Documentation">
This separate repository builds with `npm ci` and `npm run build`; publish the `out` directory on a static host with directory-index support. It needs no platform credentials or API proxy. Deployment/publication must use an explicitly chosen target; building the manual does not change either existing Vercel project.
</Tab></Tabs>

## Acceptance sequence

<Steps><Step>
### Prepare an exact release

Record source SHA, immutable image/APK/web artifacts, migrations and approved environment values. Keep the existing signed APK/backend behavior unchanged until its own qualified release.
</Step><Step>
### Verify integrated staging

Exercise real identity, permissions, callbacks, media and both clients. A green liveness endpoint or static preview alone is insufficient.
</Step><Step>
### Cut over with recovery ready

Rehearse restore/rollback, preserve new writes, set acceptance windows and alert recipients, then observe the exact deployed version.
</Step></Steps>
