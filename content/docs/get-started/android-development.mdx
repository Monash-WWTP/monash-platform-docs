**Prerequisites:** Flutter **3.44.7**, Android SDK, JDK **17** and the platform source checkout. No iOS scaffolding is supplied in the pinned import.

<Steps><Step>
### Check and compile

From the platform repository:

```sh
cd apps/citizenflood
flutter pub get
flutter analyze
flutter test
flutter build apk --debug --dart-define-from-file=staging-config.example.json
test -s build/app/outputs/flutter-apk/app-debug.apk
```

This creates a debug verification artifact, not a public release.
</Step><Step>
### Understand configuration

The source requires `API_BASE_URL`, `OIDC_ISSUER`, `OIDC_DISCOVERY_URL` and a public `OIDC_CLIENT_ID`. HTTPS is required, except explicit `LOCAL_STAGING=true` with loopback HTTP. The redirect is `au.edu.monash.citizenflood:/oauthredirect`.
</Step><Step>
### Connect an accepted environment

The sample points to localhost API 8181/identity 9100. On a physical device, localhost means the device itself; a sample build does not prove network or callback connectivity. Prepare the approved device/network and OIDC client configuration before an operational test. Do not bundle a client secret, service-role key or private signing material.
</Step></Steps>

<Tabs items={['Verification build','Public release']}><Tab value="Verification build">
Debug staging builds use synthetic configuration for compile/tests. They must not replace the published app or be presented as production-ready.
</Tab><Tab value="Public release">
Use the existing project signing identity, a larger versionCode, approved HTTPS endpoints and physical-device fresh-install/upgrade testing. Follow [Android release](/docs/operations/android-release).
</Tab></Tabs>

## Expected outcome

Analysis/tests pass and a nonempty debug APK exists. Use the API/OIDC configuration above. Supabase keys and legacy RLS do not configure this source client.
